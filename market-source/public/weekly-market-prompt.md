# 每周A股市场手记更新提示词 · v3

维护给我自己看的A股市场手记，完成本周研究、网页更新、本地归档及 GitHub Pages 发布。先验证事实，再形成判断；结论可以与上周相同，不要为周更制造变化。正文简短，重点是当前环境和应对。

## 项目与执行入口

- 仓库：https://github.com/LemuriaX/blog；线上：https://www.acgnx.top/market/。沿用 GitHub Pages。
- 当前目录有 app/、data/、package.json 时即为源码根；仓库内源码位于 market-source/。

- 保留 CNAME、首页、daily、plans、其他无关文件和历史快照。沿用米白、淡色、宋体风格，手机可读。
- 研究前执行 npm run weekly -- preflight --date YYYY-MM-DD --repo <发布仓库绝对路径>，确认 Node≥22.13、依赖、远端基线及写权限。已有脏工作区则从最新远端建立干净工作区，不覆盖用户修改。Git 登录不可用时可使用已授权 GitHub 连接器。

## 研究范围与证据

1. 只研究A股。日期取最近一个完整结束的A股交易周的最后交易日，记录 Asia/Shanghai 时区及信息截止日；不能把正在交易的一周写成完整周报。
2. 市场价格使用最终收盘；公告和新闻仅使用信息截止日当天结束前已公开内容。取数可晚于截止日，后来发布的信息不能倒填。
3. 必须联网查原始资料，优先统计局、人民银行、中国货币网、中债、交易所、基金业协会、海关、财政部；新华社等用于补充和交叉验证。链接到支持具体数字的页面。
4. 核心事实保留数值、单位、定义、范围、窗口、观测期、公开日期、取数日期和来源；原始输入与计算步骤保存在 data/inputs/YYYY-MM-DD/。这些是研究记录，不单独生成网页台账。未知日期写 null，不从文件名猜日期。
5. 区分同比/环比/年化、亿元/万亿元、流量/存量、价格回报/总回报，以及估值的利润口径。代理和正常滞后明确注明，过期数据不充当新事实。
6. 每个核心判断检查支持证据与反证。事实、计算和判断分清；缺失数据只在受影响的位置简短说明，不能填中性50或一律标中信心。

## 页面只保留以下内容

- 首屏：一句本周判断、简短理由与应对，配周期阶段、合理区间及中值。新证据直接融入相应判断，避免重复的摘要卡片。
- 四个温度计：基本面、资本供给、心理钟摆、价格压力；保留简短理由及主要指数表现。高分表示更热，不表示更好。这些是解释性判断，不计算固定加权情绪总分；无法判断用 null。
- 市场钟摆：固定20项，保留筛选、位置、证据及资料不足状态。
- 价格与价值：资产类别的安全边际与应对、攻守位置、核心仓与新增资金安排。
- 关键数据与后续行动：只列足以支持本周判断的数据和可检验的等待条件。
- 页尾：简洁参考资料链接、周报目录、更新提示词。

不生成美股内容或市场切换。不再增加情绪周线、固定评分、观测日/发布日期/取数记录、上周等待是否兑现、二层思维章节，也不将这些内容换个标题放回页面。目录页仅显示A股，旧版本不作为并列阅读入口。

## 判断与行动

- 综合趋势、盈利、资本可得性、信用、估值、广度、杠杆和心理判断牛熊；允许结构性、过渡期或暂难判断，不机械按涨跌20%定性。
- 周期先给阶段和合理区间，再给中值；0为本轮起步，100为末期，新中值以5分为刻度。区间表示主观不确定性，不是统计置信区间，不回改既有历史分数。
- 用少数人看到转机、改善成为共识、乐观被当作常识解释周期阶段；熊市写对应的悲观演化，不强套牛市叙事。
- 好资产不自动是好投资。优先看永久损失、错误定价和被迫卖出风险，以及价格要求的盈利与现金流。
- 攻守分0进攻、100防守，独立考虑估值/安全边际、信用/融资、现金流、流动性和集中风险；不由周期分机械推出，不等于仓位百分比。
- 行动分为核心仓、新增资金、等待条件、最应避免的错误。等待条件面向之后的观察，尽量注明窗口与来源；不单独复盘上周条件，不预测顶底日期。
- 参考《投资最重要的事》的价格与价值、风险、周期与钟摆、耐心及攻守平衡框架；本站分数不是书中公式。

## 每周复核20项钟摆

只维护A股的20项，名称和两极不变。每项记录位置或 null、简短依据、引用、信心、复核状态和原因。月度/季度项无新发布可以维持原位并注明“无新数据”，不要凭一条新闻重打全部位置。

- 经济现状：生机勃勃 ↔ 停滞不前
- 经济展望：正面有利 ↔ 负面不利
- 贷款机构：急于放贷 ↔ 缄默谨慎
- 资本市场：宽松 ↔ 紧缩
- 资本供给：充足 ↔ 短缺
- 融资条款：宽松 ↔ 严格
- 利率水平：低 ↔ 高
- 利差水平：窄 ↔ 宽
- 投资者：乐观、自信、渴望买进 ↔ 悲观、忧虑、无心买进
- 资产持有人：乐于持有 ↔ 急于卖出离场
- 卖家：稀少 ↔ 众多
- 市场：人群拥挤 ↔ 乏人问津
- 基金：申购门槛高、频繁发行、管理人占优 ↔ 募资困难、投资人占优
- 近期业绩：强劲 ↔ 萎靡
- 资产价格：高 ↔ 低
- 预期收益：低 ↔ 高
- 风险：高 ↔ 低
- 流行风格：激进、四处投资 ↔ 审慎、自律、精挑细选
- 正确风格：审慎、自律、精挑细选 ↔ 激进、四处投资
- 易犯错误：买进太多、高价追涨、承担过多风险 ↔ 买进太少、离开市场、承担过少风险

固定口径：近期业绩指沪深300的1周、4周、13周价格回报，盈利放基本面；广度明确股票样本，ETF数量不能替代个股广度；利差注明期限与信用等级；基金区分申购、发行、存量和市场地位，规模增长不等于净申购；预期收益讨论价格隐含要求，不给确定的未来收益率。

## 生成、验证和发布

1. 新周使用 schemaVersion=2、methodVersion=cn-brief-v1、revision=1，markets 和 informationCutoff 只含 cn。无需 sentiment、observations、reading、comparison、crossChecks。新周 history.cnSentiment、usSentiment、usCycle 均为 null，cnCycle 与A股周期中值一致；不沿用上期美股数据。清除上期修订和特殊入口字段。
2. 执行 npm run weekly -- validate --date YYYY-MM-DD，修复日期、引用、20项完整性、范围及重复记录问题。格式化后执行 npm run weekly -- prepare --date YYYY-MM-DD 生成入口、历史、目录和提示词副本。
3. 运行 npm run format:check、npm run lint、npm run typecheck、npm test、npm run build、npm run build:pages；失败不更新 latest。prepare 后改源码或提示词须重新 prepare 和构建。
4. 浏览器检查：仅A股且无已删除章节、钟摆筛选与缺失项、目录/提示词链接、窄屏可读性。此次任务已授权这些检查，记录真实结果。
5. 执行 npm run weekly -- archive --date YYYY-MM-DD --repo <发布仓库绝对路径>，将同一构建保存至本地 weekly-reports/ 和仓库 market/，核对哈希后更新目录/latest。命令支持重跑及中断恢复，冲突时不得覆盖。
6. 已发布日期的纠错或阅读改进将 revision 加一，写 revisedAt 和 revisionReason，保存到 YYYY-MM-DD/revisions/02/ 等目录。旧快照保存在归档中，不在目录并列展示原版链接；同周历史只留一条，旧数值不回改。2026-09-04为用户指定例外，旧版已删除、canonicalRevision=2、originalRetained=false；新周不得继承该例外。
7. 核对原有文件哈希、往期链接和本期资源，不提交临时文件、缓存、凭证或依赖目录。新周提交名 Weekly market update: YYYY-MM-DD；修订名 Market report revision: YYYY-MM-DD rN。若远端有新提交先整合，再发布 main，禁止强推。
8. 部署明确成功后执行 npm run weekly -- verify-online --date YYYY-MM-DD --base https://www.acgnx.top/market/，验证目录、latest、HTML、JS、CSS、提示词和数据的线上字节哈希；推送成功不等于网页已更新。
