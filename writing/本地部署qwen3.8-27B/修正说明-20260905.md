## 测试流程已修正的主要问题

| 问题 | 当前处理方式 |
|---|---|
| 超时或断流后丢失证据 | 请求前后追加 JSONL、刷写缓冲；要求 DONE 与 finish_reason，保留部分响应 |
| 失败被排除，重试掩盖首次失败 | 全部计划请求作为分母；主表固定取第一次结果，重试单独保存 |
| 内容与接口格式混在一起 | 分开计算内容正确、格式合规与任务成功；递归检查 JSON 类型及结构 |
| 代码按字符串判等 | 指定位置的代码修复比较 AST，不执行模型代码 |
| 不同测速来源混合 | 引擎值与客户端估算分列，分别记录来源、有效样本数和统计值 |
| 启动请求被当作生效证据 | 核对模型、窗口、卸载、缓存与批量配置；缺证据记 unknown/unverified |
| 不同质量组的生成条件不同 | 三组统一 Thinking＋xhigh、采样、输出预算；计数与生成使用相同模板参数 |
| 输入与生成空间冲突 | 性能、质量语料分开，检查输入、输出预算、容差和安全余量 |
| CLI 帮助省略长参数名 | 固定帮助表格宽度，区分启动失败与缺少必需参数 |
| 服务退出后端口仍被子进程占用 | Windows Job Object 管理本次进程树，等待实际退出和端口释放后切换 |
| 后台日志不可见、中文乱码 | 转发标准输出和错误输出；统一 UTF-8，退出时恢复终端设置 |
| 底层日志缺失、进度不清楚 | 归档当前阶段引擎日志；显示阶段参数、逐题结果和每 15 秒的等待状态 |
| 监控记录不完整 | 每阶段建立监控行，统一 GiB 与采样口径，未测值留空 |
