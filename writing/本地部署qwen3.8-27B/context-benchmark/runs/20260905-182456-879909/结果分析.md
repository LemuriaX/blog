## 失败原因与修复

日志与临时子进程复现实验一致：旧脚本发出终止指令后，只等待启动器退出；后台进程可能仍在释放端口。下一阶段随即启动，因此连续报端口占用。

已修改进程管理逻辑：终止本阶段的进程组后，等待子进程实际退出，再通过 Windows 监听表确认端口释放。退出等待超时会停止后续阶段，并保留已完成请求的测量数据。新的终端输出和根目录摘要会显示失败原因、完成数及待执行数。实现使用 [Windows Job Object 接口](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-terminatejobobject) 和 [TCP 监听表接口](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getextendedtcptable)。

已在 Windows 临时进程上验证同一端口连续运行三个阶段，以及启动器提前退出时的子进程清理。用户实际使用的 Python 3.13 下，4 项相关检查也已通过。最终 32 项回归测试全部通过；这些验证未加载 GPU 模型。
