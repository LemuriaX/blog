# 每周市场手记更新提示词 · v2

维护给我自己看的 A股与美股市场手记。完成本周研究、网页更新、本地归档及 GitHub Pages 发布。先验证事实，再形成判断；结论可以与上周相同，不要为周更制造变化。

## 项目与执行入口

- 仓库：https://github.com/LemuriaX/blog；线上：https://www.acgnx.top/market/。
- 源码在仓库 market-source/；当前目录直接有 app/、data/、package.json 时，当前目录就是源码根，不再嵌套另一份源码。
- 唯一分析输入：data/reports/YYYY-MM-DD.json。历史基线：data/legacy-history.json。lib/current-report.ts、lib/market-history.ts、archive/ 由 scripts/weekly.mjs 生成；不要同时手改多份数据。
- 评分规则唯一来源：lib/scoring.ts；操作细节：WORKFLOW.md。
- 线上日期目录：/market/YYYY-MM-DD/；本地：weekly-reports/YYYY-MM-DD/；latest 指向最新成功发布版本。
- 保留 CNAME、首页、daily、plans、其他无关文件和全部历史快照。沿用米白、淡色、宋体气质，正文自然、清楚、适合手机阅读。
- 研究前执行 npm run weekly -- preflight --date YYYY-MM-DD --repo <发布仓库绝对路径>，确认 Node≥22.13、依赖、远端基线及发布渠道。已有脏工作区就从最新远端建立干净工作区，不覆盖用户修改。Git 登录不可用可使用已授权的 GitHub 连接器，不反复重做分析。

## 日期、信息集与证据

1. 默认选择最近一个完整结束的交易周，记录两地最后一个已收盘交易日、时区和信息截止日。节假日允许两地日期不同，文件日期使用较晚者；正在交易的一周不能冒充完整周报。
2. 市场价格截至当地收盘，公告和新闻限各市场信息截止日当天结束前公开的内容。取数可晚于截止日，但后来发布的信息不能倒填；日内问题保留时区和时刻。
3. 必须联网查原始资料。A股优先统计局、人民银行、中国货币网、中债、交易所、基金业协会、海关、财政部；美股优先 BEA、BLS、Fed、FRED、Cboe、ICI、SEC。FactSet、AP、Reuters、新华社用于补充和交叉验证。保留支持具体数据的直接链接，不只给首页。
4. 核心观测保存数值、单位、定义、市场/样本范围、窗口、observedAt（观测截止）、publishedAt（公开日期）、retrievedAt（取数日期）、信源ID、原始输入或计算步骤。未知日期写 null 并说明，不能从文件名猜发布时间。
5. 采用最终收盘，媒体早版有差异时解释取舍。区分同比/环比/年化、亿元/万亿元、流量/存量、价格回报/总回报、全年预期/未来12个月/历史利润PE；不同口径不直接比较数值。
6. 状态统一为 verified（已核验）、lagged（正常滞后）、proxy（代理）、missing（缺失）。正常滞后注明频率与允许时效，不无限期沿用旧值。信心可选高、中、低、无法判断；资料不足不能一律写中信心。
7. 每个核心结论同时寻找支持与反证。调查与硬数据、价格与基本面冲突时并列呈现，区分事实、计算、推断与行动判断。

## 先回答三件事

网页首屏在市场切换后放三张简短卡片：

- 本周新增了什么证据？只放影响判断的变化，写明观测期。
- 哪个判断因此改变，或为何维持？区分事实变化、方法变化与主观修订。
- 上周等待条件兑现了吗？逐条引用上一期原条件，标满足、部分满足、未满足、无法判断。联合条件全部成立才算触发；没有新数据就明确说没有。

随后展示周期阶段与区间、四个温度计、情绪历史及缺口、条件复盘、20项钟摆、二层思维、价格风险与行动、信源台账。细节可以折叠，但数据缺口和比较限制必须直接可见。

## 周期、价格与行动

- 综合趋势、盈利、资本可得性、信用、估值、广度、杠杆与心理判断牛熊；允许偏牛、结构性、过渡期、暂难判断，不机械按涨跌20%定性。
- 先给阶段与合理区间，再给中值。0为本轮起步，100为末期；新中值以5分为刻度，不宣称能区分相邻1分。区间是主观不确定性，不是统计置信区间，不回改旧分。
- 用三阶段解释：少数人看到转机、改善成为共识、乐观被当作常识；熊市写对应的悲观演化，不强套牛市叙事。
- 四个温度计为基本面、资本供给、心理钟摆、价格压力。高分只代表更热。除情绪计算外，其他分数是证据支持的判断值，须写理由。
- 二层思维回答四句：共识是什么、价格计入什么、可能重要的不同判断是什么、什么还不知道。
- 好资产不自动是好投资。风险重点是永久损失、错误定价和被迫卖出，而非日常波动。
- 攻守分0进攻、100防守。独立看估值/安全边际、信用/融资、现金流、流动性和集中风险，不从周期分直接推出，也不等于仓位百分比。
- 行动分核心仓、新增资金、等待条件、最应避免的错误。条件尽量可检验，写观察窗口与信源，不预测顶底日期；逆向须有错误定价依据。
- 依照《投资最重要的事》的二层思维、价格与价值、风险、周期与钟摆、耐心、承认未知、攻守平衡框架；书中没有本站分数公式，不要伪托权威。

## 每周复核20项钟摆

两地各20项，保留下面名称和两极。每项记录位置或 null、证据、引用、信心、复核状态和原因。月度/季度项未有新发布可原位保留，标“无新数据”；不要凭一条新闻重打全部位置。资料不足可以不定位。

- 经济现状：生机勃勃 ↔ 停滞不前
- 经济展望：正面有利 ↔ 负面不利
- 贷款机构：急于放贷 ↔ 缄默谨慎
- 资本市场：宽松 ↔ 紧缩
- 资本供给：充足 ↔ 短缺
- 融资条款：宽松 ↔ 严格
- 利率水平：低 ↔ 高
- 利差水平：窄 ↔ 宽
- 投资者：乐观、自信、渴望买进 ↔ 悲观、忧虑、无心买进
- 资产持有人：乐于持有 ↔ 急于卖出离场
- 卖家：稀少 ↔ 众多
- 市场：人群拥挤 ↔ 乏人问津
- 基金：申购门槛高、频繁发行、管理人占优 ↔ 募资困难、投资人占优
- 近期业绩：强劲 ↔ 萎靡
- 资产价格：高 ↔ 低
- 预期收益：低 ↔ 高
- 风险：高 ↔ 低
- 流行风格：激进、四处投资 ↔ 审慎、自律、精挑细选
- 正确风格：审慎、自律、精挑细选 ↔ 激进、四处投资
- 易犯错误：买进太多、高价追涨、承担过多风险 ↔ 买进太少、离开市场、承担过少风险

固定定义：“近期业绩”是基准指数1周、4周、13周价格回报，不是企业利润；盈利放基本面。“广度”必须明确股票样本，ETF数量不能替代个股广度。“利差”注明期限和信用等级。“基金”区分申购、发行、存量资产和市场地位，规模增长不等于净申购。“预期收益”讨论价格隐含要求，不写确定的未来收益率。

## 情绪评分 v2

新规则从2026-09-04之后第一期启用。08.28、09.04总分保留原样，不倒填新分项冒充当时记录。methodVersion 写 sentiment-v2；指标定义、基准、窗口、阈值变化须升版本并解释。

固定原权重：趋势广度25%、资金成交杠杆25%、波动利差20%、估值拥挤15%、调查行为15%。指标、子权重、窗口、有效期和锚点以 lib/scoring.ts 的 metricRules 为唯一依据，网页读取同一份规则。

- 保存每项原始值，调用 scoreSentiment 计算，不能凭感觉填分。五个锚点对应0/25/50/75/100，线性插值并在两端截断，反向项颠倒；解释70或90分应展示插值，不改阈值凑总分。锚点是本站自定尺度，未经回测，不是收益预测模型。
- 历史分位仅使用当时可得序列：分位=(小于当前值的数量+0.5×等于当前值的数量)/样本数×100。保留区间、样本数、当前值、信源及输入文件；不满足最低样本数标缺失。
- A股基准沪深300，美股标普500。信用、杠杆等各自有固定定义，主要比较各自历史。A股调查尚未锁定连续公开序列，暂缺；选定后升版本，不临时换问卷。
- 缺失用 null，没有数据不等于中性50。未经规则预先定义的代理只作定性旁证，不纳入定量分。正常滞后在固定有效期内可纳入。
- 有效原权重至少70%，且趋势、资金、波动信用前三组各有直接观测，才给总分；否则显示“资料不足”，历史情绪值为空，不硬凑数字。
- 达标总分=有效指标原权重加权和/有效原权重，四舍五入。公开覆盖率和归一后的有效权重，同时显示缺项取0与100时的敏感性边界。明确它不是统计置信区间，不伪装可测的代理误差。
- 同版本、全覆盖、定义相同的连续两期才显示可比变化；否则说明原因、显示覆盖情况、断开折线。不能把方法变化说成市场升温降温。
- 0—20极度恐惧、21—40谨慎、41—60中性、61—80乐观、81—100亢奋。量情绪，不预测涨跌。

## 生成、验证、归档、发布

1. 完成结构化输入，包括两地分析、原始观测、条件复盘、方法信息和修订原因。执行 npm run weekly -- validate --date YYYY-MM-DD，修复日期、引用、完整性、范围及重复记录错误。
2. 执行 npm run weekly -- prepare --date YYYY-MM-DD，生成页面入口、历史、目录和提示词副本。同日同内容重跑不得重复追加；内容冲突先检查。
3. 运行 npm run format:check、npm run lint、npm run typecheck、npm test、npm run build、npm run build:pages；修复所有错误，失败不切latest。
4. 浏览器最小验收：两市场切换、历史点与不可比说明、评分折叠、钟摆筛选和缺失项、目录/提示词链接、窄屏可读性。此次任务授权这些浏览器检查，无需另问；记录真实结果，HTTP成功不等于交互测试。
5. 执行 npm run weekly -- archive --date YYYY-MM-DD --repo <发布仓库绝对路径>，把同一构建完整保存到本地和发布仓库，核对哈希后再更新两个目录和latest。可用 --local-root 指定本地周报库。命令须支持同内容重跑和中断恢复，遇不同内容拒绝覆盖。
6. 已发布日期的事实纠错或阅读改进，把 revision 加一，写修订日及原因，另存 YYYY-MM-DD/revisions/02/ 等目录并保留原版入口；不追加第二条周历史。事实纠错和后见判断分开，禁止覆盖原版掩盖变化。
7. 验证原有文件哈希、往期链接、本期资源和提示词，无关内容不变。不要提交临时文件、缓存、凭证或依赖目录。
8. 新周提交名 Weekly market update: YYYY-MM-DD；修订名 Market report revision: YYYY-MM-DD rN。提交说明写方法、缺失、修订和验证。比较远端基线，若有新提交先整合，再发布main，禁止强推。
9. 等部署明确成功后，执行 npm run weekly -- verify-online --date YYYY-MM-DD --base https://www.acgnx.top/market/，核对线上目录、latest、HTML/JS/CSS/提示词/数据与清单的字节哈希；不能凭推送成功声称网页已更新。
